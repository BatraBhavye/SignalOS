# SignalOS CI Doctor (MCP Server)

A standalone Model Context Protocol (MCP) server engineered for CI/CD failure diagnosis, root-cause analysis, and DevSecOps container vulnerability triage.

`SignalOS-CI-Doctor` exposes high-value diagnostics tools over standard input/output (`stdio`) to MCP-compatible AI clients (such as Claude Desktop, Cursor, and IDE coding agents), allowing models to inspect pipeline failures, query GitHub Actions logs, and prioritize actionable security remediation.

---

## Capabilities & Exposed MCP Tools

The server provides three well-typed tools:

### 1. `fetch_ci_logs(repo: str, run_id: int) -> str`
* **Purpose:** Queries the GitHub Actions REST API (`https://api.github.com/repos/{repo}/actions/runs/{run_id}/jobs`) to extract failed jobs, failed step names, step numbers, failure conclusions, and run URLs.
* **Authentication:** Respects `GITHUB_TOKEN` from the environment when provided (to bypass GitHub public rate limits), or falls back cleanly to unauthenticated requests for public repositories.

### 2. `diagnose_pipeline_failure(log_excerpt: str) -> dict`
* **Purpose:** Performs deterministic root-cause classification on CI/CD build logs or console traces.
* **Signatures Detected:**
  * **Dependency & Import Errors:** `ModuleNotFoundError`, `ImportError`
  * **Test Suite Failures:** `pytest` assertion errors and failing test selectors
  * **Static Code Analysis:** `ruff` and `shellcheck` lint violations
  * **Container Build Failures:** Docker build step failures and missing build context files
  * **Database Issues:** PostgreSQL connection refused, host resolution, and authentication failures
  * **Security Policy Gates:** Trivy scanner blocks and OPA policy violations
* **Output:** Structured dictionary containing `failure_category`, `suspected_component`, `deterministic_findings`, and an actionable `remediation_checklist`. Gracefully checks for local Ollama without blocking.

### 3. `triage_vulnerabilities(trivy_report_path: str) -> dict`
* **Purpose:** Parses container security reports generated by Trivy (`trivy-results.json`).
* **Filtering & Deduplication:**
  1. Filters strictly for `CRITICAL` and `HIGH` severity vulnerabilities.
  2. Deduplicates findings by `VulnerabilityID` across targets and layers.
  3. Sorts by severity (`CRITICAL` before `HIGH`) and prioritizes entries with available patches (`FixedVersion`).
* **Output:** Summary containing raw vs unique finding counts, actionable patch counts, and a sorted vulnerability triage catalog.

## Installation & Setup

### Prerequisites
* Python 3.10+ (Python 3.11 recommended)
* `pip`

### Step 1: Install Dependencies
From the repository root or inside `mcp-ci-doctor/`:
```bash
pip install -r mcp-ci-doctor/requirements.txt
```

### Step 2: Test Server via CLI
You can test the server locally using the MCP CLI inspector or by running the script directly:
```bash
python mcp-ci-doctor/server.py
```

---

## MCP Client Configuration

### Claude Desktop (`claude_desktop_config.json`)
Add the following configuration to:
* **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
* **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`
* **Linux:** `~/.config/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "signalos-ci-doctor": {
      "command": "python",
      "args": [
        "d:/personal_archive/nlp/SignalOS/mcp-ci-doctor/server.py"
      ],
      "env": {
        "GITHUB_TOKEN": "ghp_optional_token_for_rate_limits",
        "OLLAMA_BASE_URL": "http://127.0.0.1:11434"
      }
    }
  }
}
```

### VS Code / Generic MCP Settings
```json
{
  "mcp.servers": {
    "signalos-ci-doctor": {
      "type": "stdio",
      "command": "python",
      "args": [
        "mcp-ci-doctor/server.py"
      ],
      "env": {
        "PYTHONUNBUFFERED": "1"
      }
    }
  }
}
```
